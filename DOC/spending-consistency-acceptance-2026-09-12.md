# 收支與預算一致性驗收（2026-09-12）

## 範圍與結果

總覽、月度分析及訂閱頁共用月度收支模型：本地今天（含）以前的交易才是實際收支；本月未來日期交易與尚未入帳訂閱分開列示。HKD 分類預算只計實際 HKD 支出，USD／JPY 等原幣分列，不換匯。

本輪只調整前端讀取、純計算及顯示。資料 schema、訂閱 id／去重鍵、自動入帳儲存流程、Auth、Firestore rules、Functions 與依賴均未更動。工作目錄另含同日已完成的分析、交易管理及月份預算改動，不能將整份 Git diff 誤當本輪新增範圍。

## 計算規則

- 實際支出＝所選月份日期不晚於本地今天的 expense；未來 income 不加入目前收入、結餘，也不抵銷預算支出。
- 已知支出合計＝已花費＋未來交易支出＋待扣訂閱；不含尚未記錄的日常消費，因此不是完整月底預測。
- 已用百分比＝實際支出／分類預算；剩餘＝預算−實際支出；預計剩餘＝預算−已知支出。百分比文字可超過 100%，只有進度條寬度截斷。
- 同一 `subscriptionId:date` 已有 expense（含未來預填）時不再預留；採該交易記錄的金額與幣別。收入不會阻止訂閱支出預留。訂閱已停用／刪除時，既有交易仍計入。
- 未入帳的今日或逾期訂閱仍屬待扣，不假裝已花費；已停用訂閱不產生新預留。沒有設定預算的分類不顯示使用率，但其支出仍計入全部支出與總預算剩餘。
- 訂閱資料不可用時，Analysis 保留可讀的實際收支，待扣、已知合計及預計剩餘為未知；首次整頁載入失敗的總覽／訂閱顯示錯誤與重試入口，不顯示零值。後續更新失敗保留既有資料。
- Analysis 本月讀至月底以取得未來交易，但 KPI／同期比較／每日與月度趨勢仍截止今天。歷史月份不套用現有訂閱預留；年度及自訂日期分析維持既有實際期間規則。
- 月底速度估算＝目前實際支出÷經過天數×當月天數，與已知支出合計分開，不再次加上未來交易／訂閱。
- 本地日期每分鐘及視窗恢復焦點時更新；跨日後未來交易可進入實際收支，跨月重新讀取月份資料。
